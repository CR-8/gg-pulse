## 4. GG-ops: what already exists and how gg-pulse uses it

GG-ops (`my-app/`) is a production Asana-style PM platform on the **same target stack**: Next.js 16.2 App Router,
React 19.2, TypeScript strict, MongoDB Atlas + Mongoose 9, Auth.js v5 (JWT, Credentials + Google), Tailwind v4,
shadcn/ui, Zod 4, Vitest. Relevant capabilities:

- Identity: `users` (bcrypt `passwordHash`, `authVersion` for session revocation, `emailVerifiedAt`, `jobTitle`),
  `authtokens`, `loginevents`, API keys (`ggops_sk_…`), OAuth 2.1 authorization server for MCP clients.
- Tenancy: `workspaces` (unique `slug`), `workspacemembers` (`MAINTAINER|ADMIN|MEMBER|GUEST`, `ACTIVE|INVITED|REMOVED`),
  `workspaceinvites` (token links).
- PM: `projects`, `sections`, `tasks` (`TODO|IN_PROGRESS|DONE|BLOCKED`, priorities, assignees, subtasks, recurrence),
  `taskdependencies` (`BLOCKS`), `comments`, `activitylogs`, labels, custom fields, goals, saved views, DSR, timeline.
- Conventions: `{ ok, data, error }` API envelope, `ActionResult`, DAL `requireUser()`, ownership-chain checks,
  workspace-scoped queries, one model file per collection, `models.X || model(...)` bootstrap.
- Ops facts that constrain gg-pulse: `autoIndex` is off in production and **`npm run db:sync-indexes` calls
  `syncIndexes()`, which drops any index not declared in GG-ops's models**; `withTransaction` requires a replica set.

Decision (detailed in `INTEGRATION-GG-OPS.md`): gg-pulse reuses GG-ops's collection contracts for identity, tenancy
and PM so both apps can run on one database, instead of inventing a second, incompatible task model.

## 5. Preserve / replace summary

Preserve (port the behaviour, with its tests): breakage detection, webhook HMAC check, diff annotation/chunking/
validation for reviews, incremental review base selection, blame attribution, LLM provider abstraction and
interactive-first scheduling, docgen's facts→diagrams→prose pipeline with fingerprints and version history,
the MCP tool catalogue, the "repository text is untrusted data" prompt rules.

Replace: SQLite, in-process threads/queues, shared passwords, `DEV_USER`, global MCP token (and token-in-URL),
raw-SQL chat tool, plaintext secret storage, repo-specific `build.py` steps, per-person line/commit rankings,
Astro frontend, single-VM compose topology.
